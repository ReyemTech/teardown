# Geo-IP Attribution Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add sourced approximate Geo-IP data to each observed global network address.

**Architecture:** Extend the existing named network module with one allowlisted RIPEstat GeoLite lookup per global IP. Parse provider data into a typed optional model. Render a country/city summary and attribution while preserving routing results on Geo-IP failure.

**Tech Stack:** Python 3.10+, existing Fetcher/httpx and pytest. No new runtime dependency.

**Spec:** `docs/superpowers/specs/2026-11-17-geo-ip-design.md`

## Global Constraints

- No origin or physical server-location claim; a CDN address is an edge.
- Only global addresses get Geo-IP queries; keep the eight-address host cap.
- Use the shared HttpClient cache, semaphore, rate limit, and allowlist.
- Unknown or invalid values remain absent; no synthetic country/coordinates.
- Additive JSON schema version is 1.4.

## Review Focus

- Provider country `?` and `(0, 0)` coordinates must not become a location.
- Multiple provider locations must select the strongest valid coverage.
- Malformed data must leave ASN and prefix intact.
- Private IPs must not be sent to RIPEstat.
- CDN edge wording must remain explicit in rendered output.
