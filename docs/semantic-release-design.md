# Automatic releases

## Intent

Merging a Conventional Commit to `main` should release a new version of
`tech-teardown` without manual tagging. The package keeps PyPI OIDC trusted
publishing and both `teardown` and `tech-teardown` commands.

## Approaches

- **Selected: Python Semantic Release in `release.yml` on `main` pushes.** It
  calculates the version from commits, updates `pyproject.toml`, creates the
  tag and GitHub release, then the same workflow builds and publishes through
  the existing PyPI trusted publisher. No extra token is needed.
- A separate tag workflow would need a token or app to trigger GitHub Actions
  from the generated tag. It adds a credential and another handoff.
- Manual dispatch preserves an approval step but does not meet the requested
  automatic release behavior.

## Release path

PR CI tests Python 3.10–3.14. After merge, the release workflow tests the
merged commit, calculates a version from Conventional Commits, and publishes
only if it created a release. `fix` and `perf` bump patch; `feat` bumps minor;
breaking changes bump major. `chore`, `docs`, and `ci` alone do not publish.
The release job has GitHub contents write access; the separate publish job has
OIDC access to PyPI. Both jobs are serialized per branch.

## Constraints

Keep the existing `v{version}` tags and 0.x versioning. The release commit is
generated by GitHub Actions, so it does not retrigger workflows. PyPI's trusted
publisher continues to match `.github/workflows/release.yml`.
